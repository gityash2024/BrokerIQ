# Super Admin business data workspace

The existing Super Admin routes exposed platform/moderation data and selected firm/Inventory/Team views, while core Broker CRM endpoints often required a firm context. There was no single all-firms drill-down across current/archived business records. The new /admin/business workspace defaults to all firms, including inactive firms and archived records; choosing no firm never means first active firm.

A fixed resource catalogue covers Leads, Broker Requirements, Import batches, Source entries, Inventory, Listings, Conversations, Messages, KYC submissions, Shifts, Follow-ups, Visits, Invoices, Automation rules/runs, Webhook events, Background jobs and AI usage. No arbitrary Prisma model, column or sort is accepted. Search values, identifiers, statuses/dates and selections are bound parameters; only hard-coded SQL identifiers/joins can enter query structure. Record counts and paginated lists use the same filters inside repeatable-read snapshots. A module-total panel follows hierarchy/date filters; its copy explicitly distinguishes record-list search/status/archive filters.

Firm/member pickers search and page rather than using a first30 cap. Suspended firms and all existing account roles remain discoverable. Unsupported member/archive semantics produce an error instead of silently ignoring a filter. Detail views display the permitted explicit projection, record/firm/member identity and known related-record links. Back navigation preserves resource/firm/member/search/status/archive/date/sort/page. KYC review and Inventory retain links to their existing authorized workflows. This workspace reads data and does not add approval, messaging or financial mutation powers.

Secrets, integration settings, provider payloads, Message.meta, KYC numbers/storage keys/URLs, invoice public access tokens and arbitrary user credentials are not projected. Existing authenticated KYC preview remains in KYC. Background job firm identity uses known event/rule/import/lead relationships or its explicit org payload; unassociated jobs remain platform/unassigned rather than being attributed to a guessed firm. Raw potentially sensitive provider error/log payloads are not rendered here. Detailed failure diagnosis, targets/performance, exact shift locations and permitted administrative actions continue through their dedicated modules and still need complete launch acceptance.

Filtered/selected summary CSV uses the complete matching dataset, independent of visible pagination; selected IDs must all still match. Limit50,000 records or2,000 selected IDs fails explicitly, never silently truncates. UTF-8 BOM, quoted cells and spreadsheet-formula escaping are applied. This is an overview CSV (identity/firm/member/title/status/date); module-specific complete XLSX/PDF/data exports remain separate unfinished gates. Sensitive reads/exports are audited and responses private/no-store.

Six real PostgreSQL/HTTP cases cover all18 resource queries, actual linked Source/Message/Job/Invoice detail projections, inactive/archived firms, pagination/filter/count consistency, cross-firm selection validation, all five non-Super-Admin roles, stale demotion, injection-shaped search, invalid resource/status/date/member filters, complete-filter export and chosen IDs, formula escaping, private KYC/reference/secret exclusion and read audit records. No provider request or staging fixture is used. Initial no-ids export failed because the generic ZodPipe substitutes{} for undefined; validating an object-wrapped optional IDs query fixed it, with explicit missing/empty/repeated-query cases. Workspace types pass. Browser visual/accessibility, staging read journeys, exhaustive record-field coverage, mobile Super Admin experience and complete product sign-off remain OPEN. Source is AFTER Build46 and must ship in a new pinned release.
