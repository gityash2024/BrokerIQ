# Channel drafts, mobile actions and task boundary checkpoint

WhatsApp retains its legacy pending-draft key; SMS and Email now use separate lead/channel keys on web/mobile. Pending drafts never enter URLs. Mobile uses the existing keyed SQLCipher connection and a serialized SQLite transaction to transfer a pending draft to a resolved conversation. Different existing conversation drafts are retained along with the incoming pending draft; account changes cancel the transfer. Web applies the same conflict-preservation rule synchronously in account-scoped session storage. No sent business message was generated by these checks.

Native Follow-ups, Visits and Pipeline expose authorized internal WhatsApp/SMS/Email actions, matching the Lead entry. Email is offered when an actual email exists; missing integration remains an actionable settings error rather than an external-app redirect. Visit/follow-up payloads include the already authorized lead email.

An additional permission defect was found: an old follow-up could remain assigned to Agent A after its lead was reassigned to B, allowing A to read contact metadata and mutate that task. Lists and mutations now require both task and current lead assignment/firm ownership. Mutations lock the lead and task rows and recheck scope before writing, so assignment changes cannot race the check. Concurrent completion retries create one activity; reopening clears completedAt; reschedule dates require valid offset-aware datetimes. The next-follow-up calculation is committed with the task update.

Validation:82 mobile tests with real SQLite transfer/conflict/account-switch cases,59 shared tests,16 real API/PostgreSQL permission/visit cases including duplicate completion and stale-agent denial; workspace types pass; scoped ESLint0 errors (existing warnings remain). No fixtures were written to staging. Physical/native/provider acceptance remains open. These changes require a release newer than Build41 before they are considered shipped.

This checkpoint does not complete channel automation: SEND_EMAIL/team actions are still restricted in Broker-first automation, SMS actions and complete reminder/property-sharing channel choices remain open, and live Gmail/Textbee acceptance is not inferred from UI actions or provider stubs.
