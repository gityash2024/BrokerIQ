# ZIP stream retention correction — after Build52, not yet published

The installed fflate0.8.3 implementation retains compressed chunks for an entry whose start() is never called. The text-only ZIP reader skipped binary entries without starting them. Even though it did not inflate images, ignored compressed media could accumulate in memory for the whole export. The previous bounded-memory comment therefore overstated what the library actually did.

Ignored files now use a discard decoder for their compression method and are consumed without inflating or retaining their payload. Stored/deflated text decoders are restored before each later TXT entry. Transport chunks remain4096 bytes, expanded text stays capped at300MB and individual messages/lines at2M characters. Archives additionally stop after10,000 entries or a filename longer than1024 characters, with the original retained for review. No archive path is written to the filesystem.

Eight contract tests pass, including a library-buffer retention regression with12 incompressible64KiB media entries, both stored and deflated text after discarded files, excessive filename/entry count, chunk integrity, UTF-8, truncation and system-event separation. API typecheck passes; scoped ESLint0 errors/6 pre-existing warnings.

The unchanged original Rahul export (SHA2568b17a3736af80d10d69f24d52f41b6c1df05894f39e5780d035425f66e899b08) was read without CRM writes. Before/after both yield1,897 entries:1,354 posts and543 system events, one TXT and39 attachments. Direct instrumentation of the archive reader shows peak retained compressed entry payload8,562,593 bytes before and0 after. This is a specific internal-buffer metric, not process RSS, peak heap, load/soak evidence or semantic precision/recall. The first diagnostic probe loaded the package's different absolute-path entry point; its assertion rejected the invalid measurement. The corrected probe resolves the same conditional package entry as the application.

Original images/videos remain in the encrypted ZIP. This correction does not implement associated embedded-photo OCR. Photos still need bounded extraction, per-message filename association, reviewed OCR, retry-safe private references and authorized previews before that acceptance row can close. Raw chats were not committed, imported or used for automatic model training. Active staging remains pinned Build52; this source correction awaits a later verified release.
