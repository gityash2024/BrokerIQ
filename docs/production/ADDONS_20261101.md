## Password followed by email OTP

- Normal email/password login requires password verification followed by an OTP sent to the account's registered email. Final session/access tokens are issued only after the required factor succeeds.
- Preserve existing persistent-session refresh behavior. Opening an already valid session is not a new password login.
- Bind short-lived OTP challenges to account, purpose and login attempt/device. Hashed codes, bounded attempts/resends/expiry, replay protection, rate limits, safe errors and server audit.
- Apply web/mobile and every password-login role, including Super Admin. Verify the transactional mail provider before production enforcement so existing accounts are not locked out.
- Session-limit replacement happens only after the required authentication factors. Existing passwordless, recovery, invitation and Google routes must be reconciled explicitly so they cannot bypass the intended policy or break existing account onboarding.
- Phone is not made mandatory yet. Design the factor contract for later verified mobile + SMS OTP requirements; no pretend SMS verification before the provider/device is operational.
- Backward-compatible old-client/update-required behavior and login/recovery/provider-outage journeys remain production release gates.
