# Follow-up dataset and date contract

The old list returned at most500 rows; its web badge counted that returned array and could understate the actual work. Arbitrary status/date query strings were cast into Prisma and date presets used the server's local timezone. A view could overwrite the caller's custom range. The old Done UI silently restricted scheduled due dates to14 days.

New web/mobile clients use validated server pagination, deterministic due/created/completed ordering plus ID tie-breaker, full-dataset counts, scoped lead/note search, assignee selection, inclusive IST custom due-date ranges and all four statuses. Done lists every completed task in descending completion order, with explicit optional due-date filters. Native infinite scrolling retries a failed next page without hiding already loaded rows; web exposes page/total controls. Summary queries refresh each minute and native pull-to-refresh also updates badges.

`today` retains the existing “आज तक” meaning: pending through the current IST day's end, including overdue work. `overdue` is pending before now. `upcoming` begins after that day's end, so the tomorrow queue does not repeat later-today entries. Custom ranges intersect these views. Tomorrow snooze is10AM IST on both clients, independent of server/device timezone. Invalid calendar days, offset-less timestamps, reversed ranges, unknown statuses and invalid pagination return400. Array responses for older clients remain backward-compatible and retain their historical500-row cap; the new clients explicitly request the paginated response.

Counts, search and every page apply both task ownership and the lead's current firm/assignee. Real Nest/PostgreSQL tests paged503 authorized tasks across six pages with no duplicate/missing ID, excluded another agent's tasks and stale assignments, denied another firm's counts, checked an IST midnight boundary and proved custom ranges cannot be overwritten by a view. Shared boundary/validation tests and workspace typechecks pass. This is source/database evidence; final deployed web/native UI and reminder/push delivery remain separate gates. Follow-up creation retry/idempotency and all-channel reminders are not closed by this change.
