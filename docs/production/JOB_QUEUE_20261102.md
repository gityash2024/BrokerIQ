## Bounded extraction, UTC scheduling and lease ownership

Source correction prepared after Build51; staging still runs Build51 until a later release manifest explicitly records publication. Heavy `import.extract` work previously shared a ten-job batch with ordinary work. A large import held the polling batch open, while multiple imports could start together. The only import heartbeat ran after every250 messages, so a long image/OCR step did not renew its lease. Completion/retry writes also did not require the original RUNNING attempt.

Claim transactions now take a short PostgreSQL advisory transaction lock, select up to10 ordinary due jobs and at most one heavy import across workers, then release the transaction before handlers run. Heavy work does not hold subsequent ordinary polling batches. All handlers receive a30-second periodic heartbeat; module rejection, heartbeat, completion and retry writes require the same RUNNING attempt. Pending/completed/failed or superseded snapshots cannot invoke a handler. The old message-count heartbeat has been removed. Retries retain bounded backoff; exhausted outbound deliveries remain FAILED for manual provider-status review.

The real local PostgreSQL session uses Asia/Kolkata. Prisma timestamp-without-zone values are UTC, but raw SQL now() was compared in the session timezone: a newly renewed heartbeat could be recovered as stale. Claim/recovery comparisons now explicitly use timezone('UTC', now()). Transactional Gmail, SMS and reminder outboxes pass an explicit JavaScript runAt date instead of relying on a session-sensitive database default. This does not change the global database timezone.

Housekeeping no longer deletes DONE jobs after seven days. Their durable operational history remains available to the Super Admin workspace; pending cancellation semantics are unchanged. No historical jobs are recreated and no business records are deleted.

The new real-PostgreSQL capacity suite uses a disposable, isolated Job schema, with simultaneous worker claims, ordinary work during a blocked heavy handler, future scheduling, backoff, late completion/failure fencing, four invalid lease states, a real31-second heartbeat and stale/exhausted recovery. Targeted five-suite regression39/39 passed. Initial reminder test fixtures directly executed a PENDING job; they now persist the real RUNNING claim first, and verify that a repeated completed snapshot does not deliver twice.

Full regression also exposed six historical suites sharing an Admin session without logging it out. Each suite now releases only its own refresh-token session during cleanup; the production five-device cap is unchanged. A negative provider test explicitly disables private disk storage for that assertion so a configured local upload provider is not mistaken for missing integration. Test-run email/domain suffixes must be DNS-safe (underscores are invalid in fixture domains).
