# Super Admin Inventory reconciliation — source checkpoint

The old `/admin/inventory` explicitly selected the first returned firm, then its first returned member. Even its `pageSize=100` member request was backed by a fixed30-row endpoint. All-firms visibility was therefore lost in frontend state, despite an API that already supported all firms. Its separate publish action sent an empty body to the strict publication-preview API, and CSV exported only the currently loaded15-row page using unsafe hand-quoting. This was incomplete source implementation, not just an old APK/cache defect.

Broker and Super Admin Inventory now mount the same property workspace inside their existing role-protected layouts. Super Admin starts with all firms/all members, uses lean searched paginated hierarchy choices, sees each property's firm, and must explicitly choose a firm before creation. No broker layout is opened for Super Admin. Private source text/image previews remain available inline; source-review navigation requiring a broker layout is omitted from this screen.

The shared workspace preserves complete detail/edit, independent floors/units, source evidence, Rent/Sale pricing, contacts, brokerage/tenant terms, record date, card/table, sorting, filters, reviewed publication and the existing editable WhatsApp owner/client pitch. The pitch no longer calls every record verified, invents Rent for unknown purpose, formats Sale as rent, duplicates the rupee sign or doubles an existing91 phone prefix. It remains an explicitly opened external WhatsApp preview; this does not close the planned all-channel internal messaging work.

Filtered CSV uses the same authorization/filter/order builder as listing, ignores UI pagination, and reads a repeatable PostgreSQL snapshot. Selected exports intersect selection with authorization and current filters. UTF-8 BOM, escaped quotes/newlines, formula-safe cells and phone text are preserved; exports are private/no-store and audited. Above50,000 matching rows it returns an explicit narrowing error without creating a partial file; asynchronous larger exports remain an operational extension. No source files/KYC/credentials are included in export.

Archive remains reversible. Admins can filter archived rows and restore their authorized private records without automatically republishing. Agents cannot access archived datasets/restore. Mutation authorization is repeated after the record lock; reassignment is validated against the locked property's actual firm, not an optional caller-provided firm. A Super Admin cross-firm assignment loophole was closed. All-firms lead-match counts now use the corresponding property's own firm instead of the first page item's firm.

Six new real-PostgreSQL journeys cover all-firms visibility, same-firm match counts,36-member pagination, lean responses/role denial, complete57-row export regardless of UI page, selected/foreign export privacy, formula/phone safety, strict dates, cross-firm reassignment denial, explicit-firm Sale creation and reversible archive without republish. Together with existing publication/permission/CSV regressions:29/29 passed. The first broader run lacked seeded locality master data; after seeding only this isolated test database, those29 passed. Workspace typechecks passed; scoped ESLint has no errors (existing `any` warnings remain).

A broader suite then passed360 tests with27 configuration skips and one loopback connection timeout in the old Growth test harness. The harness now retains a single loopback listener for its dependent requests; the complete rerun is recorded separately. No fixture touched connected staging. UI visual checks remain blocked by local browser access, installed-device tests remain user-deferred, and these changes are not in public Build43 until a new pinned release.

Complete API rerun after the loopback harness correction:361 passed,27 configuration skips (49 suites passed,4 skipped),41.577 seconds. This is isolated API/database acceptance, not Chrome/device/provider acceptance.
