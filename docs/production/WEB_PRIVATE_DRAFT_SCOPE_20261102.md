# Web private drafts and asynchronous workspace ownership

Shipped in pinned Build51,a34015c/v2.3.10, with independently matching public APK/web/runtime/landing identity. Chrome visual/multi-tab acceptance remains OPEN.

The web counterpart used account-only capture/Inbox keys. Auth changes deleted every Inbox sessionStorage key; same-user role/firm changes could retain form state, and an old A → B → A HTTP response could pass a string-only guard. Upload signing and final binary/XHR reads did not carry a durable original-operation fence.

StoredAuth now has a random workspace-context revision. Normal token refresh retains it; account/role/firm changes replace it. Persistence makes another tab's change detectable before the storage event arrives. Legacy sessions rotate safely without a forced extra logout. Old401 responses cannot refresh a different session, and a new workspace refresh does not wait for an old one. Binary reads, signed upload results, capture chunks and the final /auth/me state update use original context checks. Protected form content remounts by scope/revision, including the Capture workspace.

New capture and Inbox drafts use non-extractable AES-GCM keys and IndexedDB namespaces for account+role+firm. Authenticated encryption binds each payload to its exact target. Lost keys fail without replacing existing ciphertext. Logout/account changes clear in-memory key caches but preserve storage. Legacy capture ciphertext remains unchanged and requires ownership review or an explicit separate draft. No unknown firm/role is invented.

Old Inbox sessionStorage text is copied into encrypted, unscoped quarantine and decrypted for exact readback verification before the unchanged plaintext storage item is removed. A failed save leaves the original plaintext in place. If an old editor changes the text during migration, that changed original remains until its own verified copy exists. The current-role composer receives only a new scoped draft and a metadata warning; automatic historical ownership recovery is not claimed.

New Inbox drafts and provider retry IDs remain encrypted. Per-context serialized writes preserve rapid typing/clearing order and avoid blocking a new workspace on an old pending save. Shared-draft moves use encrypted compare-and-swap in an IndexedDB transaction: a simultaneous destination edit preserves both originals. Moving a draft onto itself does not delete it. Composer reads have target-aware readiness; old text cannot be saved/displayed as a newly selected target. Sends flush the current draft and preserve retry identity before network work. Lead action content stays out of URLs and history.

Validation:19 Node storage/HTTP ownership cases using real Node WebCrypto and explicitly in-memory fake-indexeddb,104 mobile tests, workspace typechecks and changed-source lint with zero errors. The Node suite covers cross-tab nonce changes, transparent/legacy/concurrent refresh, scoped encryption, key loss, AAD mismatch, encryption interruption, legacy preservation/readback failures, compare-and-swap conflicts, self-moves, ordered writes, private binary reads and late signed-upload results. CI now includes this separate storage contract suite. It is not a real browser, physical handset, live-provider or all-product acceptance. Reference for the test adapter: https://github.com/dumbmatter/fakeIndexedDB .
